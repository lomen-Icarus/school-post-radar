# School Post Radar — радар школьных достижений Чувашии

Telegram-бот, который дважды в день просматривает ленты ВКонтакте всех школ Чувашии
(реестр: 372 школьные записи, 365 сообществ, 23 муниципальных образования) и присылает
подписчикам посты о достижениях учеников: победы и призовые места на олимпиадах,
конкурсах, соревнованиях, награды и грамоты, поступление в вузы, поездки в вузы и на
олимпиады. Цель — чтобы факультет успел поздравить ребят в комментариях под постом.

## Возможности

- **Равномерная нагрузка.** Сообщества обходятся по очереди в двух окнах — с 08:00 до 12:45
  и с 17:00 до 20:45 (МСК): к 13:00 и к 21:00 готова свежая пачка. Ход обхода хранится в базе,
  после перезапуска бот продолжает с того же места и догоняет пропущенное.
- **Классификация «достижение / не достижение».** Быстрый фильтр по ключевым словам отсекает
  явно нерелевантные посты, остальные проверяет Claude и возвращает структурированный ответ:
  заголовок, суть в 1–2 предложениях, имена учеников, тип (олимпиада, конкурс, спорт, награда,
  поступление, поездка), уверенность. Без ключа Anthropic работает режим «только ключевые слова».
- **Гибкая доставка.** Дайджест по расписанию (по умолчанию 13:00 и 21:00), 1–6 отправок в день,
  раз в N дней, свой часовой пояс — или режим «сразу»: карточка приходит, как только пост найден.
- **Территории.** 23 муниципальных образования (21 округ + Чебоксары и Новочебоксарск) включаются
  и выключаются кнопками, по умолчанию включены все.
- **Обратная связь.** В карточке кнопки «Не достижение» и «Поздравили»: отклонённый пост больше никому
  не показывается, обработанные отмечаются.
- **Без повторов.** Каждый пост доставляется получателю один раз; глубина просмотра — 48 часов.

## Быстрый старт

```bash
git clone https://github.com/lomen-Icarus/school-post-radar.git
cd school-post-radar
cp .env.example .env         # заполните BOT_TOKEN, VK_ACCESS_TOKEN, ANTHROPIC_API_KEY, ADMIN_IDS
docker compose up -d --build
docker compose logs -f
```

Без Docker:

```bash
python3.11 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
radar init-db          # создаст data/radar.sqlite из реестра data/registry_seed.sqlite
radar resolve          # разрешит 98 коротких адресов ВК в числовые id (нужен VK-токен)
radar run              # запуск бота
```

Проверки: `ruff check radar tests && pytest -q`.

## Что нужно заполнить в `.env`

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | Telegram id администраторов через запятую (узнать: [@userinfobot](https://t.me/userinfobot)). Им доступны `/scan_now`, `/resolve`, `/stats`, `/check` |
| `ALLOWED_USER_IDS` | пусто — подписаться может любой; иначе список id, кому разрешено |
| `VK_ACCESS_TOKEN` | **сервисный ключ доступа** приложения ВКонтакте (см. ниже) |
| `ANTHROPIC_API_KEY` | ключ API Anthropic для классификации (без него — только ключевые слова) |
| `CLASSIFIER_MODEL` | модель, по умолчанию `claude-opus-5`; дешевле — `claude-sonnet-5` или `claude-haiku-4-5` |
| `SCAN_WINDOWS` | окна сканирования, по умолчанию `08:00-12:45,17:00-20:45` (в `TIMEZONE`) |
| `MONITOR_SCOPE` | `all` — все 365 найденных сообществ, включая неподтверждённые кандидаты (по умолчанию); `official` — только 59 сообществ с подтверждённой официальной связью |
| `MIN_CONFIDENCE` | порог уверенности классификатора для уведомления, по умолчанию 0.6 |

### Токен VK

Для чтения открытых стен подходит **сервисный ключ доступа** приложения — он бессрочный, не требует
прав (scope) и по официальной схеме API разрешён для `wall.get`, `wall.getById`, `groups.getById`,
`utils.resolveScreenName`.

1. Откройте кабинет [VK ID для бизнеса](https://id.vk.ru/about/business/go) → «Создать приложение»
   (тип Web / «Сайт»; для приложений может требоваться подтверждённый бизнес-профиль).
2. В настройках приложения найдите **«Сервисный ключ доступа»** и скопируйте его в `VK_ACCESS_TOKEN`.
3. Проверьте одним запросом (должен вернуться список постов):

   ```bash
   curl "https://api.vk.ru/method/wall.get?owner_id=-10812563&count=1&v=5.199&access_token=$VK_ACCESS_TOKEN"
   ```

Особенности:

- Сервисный ключ **не** умеет `execute` (пакетирование), поэтому бот делает по одному вызову
  `wall.get` на сообщество — 365 вызовов на проход при лимите от 5 запросов в секунду занимают
  пару минут и в любом случае размазаны по окну. `VK_USE_EXECUTE=1` включайте только с
  пользовательским токеном.
- Закрытые сообщества сервисным ключом не читаются (ошибка 15). После трёх таких ошибок сообщество
  отключается от опроса, список виден в `/stats`.
- Старые способы получить «вечный» пользовательский токен (Implicit Flow, чужие client_id вроде
  Kate Mobile) в 2025–2026 годах VK заблокировал; новые пользовательские токены VK ID живут час
  и требуют обновления. Поэтому сервисный ключ — основной вариант.

### Ключ Anthropic и стоимость

Классификатор вызывается только для постов, прошедших фильтр ключевых слов (обычно 10–30 % новых
постов). Один запрос — ~1–2 тыс. входных токенов (системная инструкция кэшируется) и ~150 выходных.
При 200–300 проверяемых постах в день на `claude-opus-5` это порядка $1–3 в день; `claude-sonnet-5`
примерно в 2,5 раза дешевле, `claude-haiku-4-5` — в 5 раз. В коде включён серверный fallback на другую
модель при отказе классификатора (`CLASSIFIER_FALLBACKS=1`); если аккаунт не поддерживает эту
бета-функцию, бот сам отключит её.

## Как устроен бот

```
radar/
  config.py            настройки (.env)
  registry/            23 муниципальных образования и сопоставление «район из реестра → округ»
  db/                  SQLite: миграции поверх реестра, слой доступа к данным
  vk/                  клиент VK API: лимит частоты, wall.get / execute, разрешение адресов
  classify/            ключевые слова + Claude (структурированный JSON)
  pipeline/
    schedule.py        окна сканирования, расчёт времени дайджестов
    scanner.py         обход сообществ по тикам, сохранение постов, кандидаты
    notifier.py        карточки, дайджесты, учёт доставок
    scheduler.py       APScheduler: тик обхода, рассылка дайджестов, обслуживание
  bot/                 aiogram 3: меню, расписание, территории, статус, обратная связь, админ-команды
tests/                 pytest (реестр подключается как есть)
data/registry_seed.sqlite   исходный реестр школ (только чтение; рабочая база — копия)
```

### Данные

Рабочая база `data/radar.sqlite` создаётся копированием реестра `data/registry_seed.sqlite`
и дополняется миграциями (`radar/db/migrations/*.sql`):

- `municipalities` — 23 территории, `units.municipality_id` — привязка каждой площадки;
- `notification_profiles`, `notification_region_settings` и представления `v_notification_regions`,
  `v_notification_targets` — в точности по описанию из `notifications.md` реестра
  (`profile_id = telegram:chat:<chat_id>`, исключения хранятся только для изменённых территорий);
- `subscribers` — режим, расписание, часовой пояс, формат; `deliveries` — кто что получил;
- `communities.resolved_group_id` — разрешённые короткие адреса, `duplicate_of` — сообщества, которые
  оказались одним и тем же по числовому id;
- `posts`, `achievement_candidates`, `community_cursors`, `scan_runs` — посты, результаты
  классификации, курсоры и ход обходов.

### Цикл сканирования

1. Раз в `SCAN_TICK_SECONDS` (5 минут) планировщик вычисляет, какая доля сообществ должна быть
   обработана к текущему моменту окна, и обрабатывает ровно её (около 6–7 сообществ за тик).
2. У каждого сообщества запрашиваются последние `WALL_COUNT` постов; сохраняются только новые и
   не старше `LOOKBACK_HOURS`. Репосты учитываются (текст репоста добавляется к посту).
3. Новые посты классифицируются; прошедшие порог попадают в `achievement_candidates`
   с привязкой к школе и территории.
4. Подписчикам в режиме «сразу» карточки уходят немедленно; дайджесты собираются из ещё не
   доставленных кандидатов в назначенное время.
5. Если бот был выключен и окно прошло, незавершённый обход догоняется порциями по
   `CATCHUP_MAX_PER_TICK`.

## Команды бота

| Команда | Описание |
|---|---|
| `/start`, `/settings` | главное меню и настройки |
| `/regions` | территории |
| `/status` | что происходит сейчас: окно, последний обход, следующий дайджест |
| `/digest` | прислать накопленное сейчас (расписание не сдвигается) |
| `/pause`, `/resume` | пауза и возобновление |
| `/tz Europe/Moscow` | часовой пояс расписания |
| `/scan_now` (админ) | полный обход всех сообществ немедленно, с прогрессом |
| `/resolve` (админ) | разрешить оставшиеся короткие адреса ВК |
| `/stats` (админ) | статистика: подписчики, сообщества, ошибки опроса |
| `/check <ссылка или текст>` (админ) | прогнать классификатор на конкретном посте |

Бота можно добавить и в групповой чат факультета — чат станет отдельным подписчиком со своими настройками.

## Развёртывание

- **Docker:** `docker compose up -d --build`; база живёт в томе `radar-data`.
- **systemd:** пример юнита в `deploy/school-post-radar.service` (каталог `/opt/school-post-radar`,
  пользователь `radar`, `.env` рядом).
- Обновление реестра: замените `data/registry_seed.sqlite` и удалите рабочую базу — либо
  перенесите настройки подписчиков вручную (таблицы `subscribers`, `notification_*`, `deliveries`).

## Известные ограничения

- Реестр содержит 308 сообществ-кандидатов без подтверждения принадлежности школе; в режиме
  `MONITOR_SCOPE=all` они опрашиваются наравне с подтверждёнными. Ошибочные группы отключаются кнопкой
  «Не достижение» на уровне поста; отключить сообщество целиком можно в базе (`communities.scan_enabled = 0`).
- Общая группа нескольких школ относится ко всем их территориям: пост уйдёт подписчику, если включена
  хотя бы одна из них.
- Активность сообществ заранее не проверена: часть групп может быть пустой или закрытой.
