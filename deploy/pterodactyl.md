# Запуск на панели Pterodactyl

Проверено на панели `panel.frienworld.space` (Pterodactyl). Боту нужен обычный «Python»-сервер:
игровые образы (Minecraft и подобные) не подойдут.

## 1. Создать сервер

В панели создайте сервер с яйцом (egg) **Python Generic** (иногда называется «Python App»,
«Generic Python» или «Bot / Python»). Требования скромные:

| Параметр | Значение |
|---|---|
| Память | 512 МБ (хватит; 1 ГБ с запасом) |
| Диск | 2 ГБ |
| CPU | 50–100 % одного ядра |
| Версия Python | 3.11 или 3.12 |

Порты боту не нужны: он сам подключается к Telegram (long polling), входящих соединений нет.

## 2. Загрузить код

Вкладка **Console**, когда сервер запущен, либо встроенный терминал:

```bash
git clone -b main https://github.com/lomen-Icarus/school-post-radar.git .
```

Точка в конце обязательна: файлы должны лежать прямо в `/home/container`, а не в подпапке.
Если каталог не пуст, сначала очистите его через файловый менеджер.

Без git: скачайте ZIP ветки на GitHub, распакуйте и загрузите содержимое через вкладку **Files**
так, чтобы `bot.py`, папка `radar/` и папка `data/` лежали в корне.

## 3. Создать `.env`

Вкладка **Files** → **New File** → имя `.env`. Содержимое (замените значения):

```
BOT_TOKEN=123456:ABC...
ADMIN_IDS=ваш_telegram_id
VK_ACCESS_TOKEN=vk1.a...
ANTHROPIC_API_KEY=sk-ant-...
TIMEZONE=Europe/Moscow
```

Остальные параметры имеют разумные значения по умолчанию, полный список — в `.env.example`.
Файл `.env` виден только владельцу сервера; в репозиторий он не попадает.

## 4. Настроить запуск

Вкладка **Startup**:

- **Startup Command** (или переменная с именем скрипта): `python bot.py run`
- Переменная **REQUIREMENTS_FILE** (если есть в яйце): `requirements.txt` — тогда зависимости
  ставятся автоматически при каждом старте.
- Если такой переменной нет, поставьте зависимости один раз в консоли:

  ```bash
  pip install --user -r requirements.txt
  ```

## 5. Первый запуск

```bash
python bot.py init-db        # создаст data/radar.sqlite из реестра школ
python bot.py check-token    # проверит, что ключ ВК читает стены сообществ
python bot.py resolve        # разрешит 98 коротких адресов ВК в числовые id
```

Затем нажмите **Start**. В консоли должно появиться:

```
Бот запущен. Окна сканирования: 08:00-12:45,17:00-20:45 (Europe/Moscow)
```

Напишите боту `/start` в Telegram: придёт меню настроек. Команда `/status` покажет, идёт ли
сканирование прямо сейчас.

## 6. Автодеплой из GitHub

Схема: push в ветку деплоя → GitHub Actions (`.github/workflows/deploy.yml`) прогоняет
`ruff` и `pytest` → через Client API панели перезапускает сервер → при старте яйцо
Python Generic само делает `git pull` и `pip install -r requirements.txt`. Если тесты упали,
сервер не трогается. Код в контейнер не копируется по SFTP: его забирает сам сервер.

### Один раз в панели (вкладка **Startup**)

| Переменная | Значение |
|---|---|
| `GIT_ADDRESS` / Git Repo Address | `https://github.com/lomen-Icarus/school-post-radar` |
| `BRANCH` / Install Branch | `main` |
| `AUTO_UPDATE` / Auto Update | `1` (включено) — `git pull` при каждом старте |
| `PY_FILE` / App py file | `bot.py` (без аргументов запускает бота) |
| `REQUIREMENTS_FILE` | `requirements.txt` |
| `USER_UPLOAD` | `0` |

`git pull` срабатывает, только если в `/home/container` есть папка `.git`, то есть код был
получен через `git clone` (шаг 2 или **Reinstall** на пустом сервере). Если файлы залиты
вручную, перенесите `.env` и `data/radar.sqlite` в сторону, очистите каталог, сделайте
`git clone` и верните эти два файла: они в `.gitignore`, и `git pull` их не трогает.

Не редактируйте в панели файлы, которые лежат в git: из-за локальных правок `git pull`
откажется обновлять код, и бот молча запустится со старой версией (в консоли будет ошибка git).

### Один раз в панели (ключ API)

**Account → API Credentials → Create**: описание `github-deploy`, при желании ограничьте
IP-адресами (у GitHub-раннеров они меняются, поэтому обычно поле оставляют пустым).
Ключ вида `ptlc_...` показывается один раз.

### Один раз в GitHub (Settings → Secrets and variables → Actions)

- **Secret** `PTERODACTYL_API_KEY` — ключ из панели.
- **Variable** `DEPLOY_BRANCH` — не нужна: на сервер уходит ветка `main`. Задайте, только если
  захотите выкладывать другую ветку.
- Необязательно: `PTERODACTYL_PANEL_URL` (по умолчанию `https://panel.frienworld.space`)
  и `PTERODACTYL_SERVER_ID` (по умолчанию `75511c5e`).

Ручной запуск: вкладка **Actions → CI / Deploy → Run workflow** (выберите ветку деплоя).

Статус `running` панель ставит, когда в консоли появляется строка готовности из настроек яйца.
Попросите администратора панели задать её как `Бот запущен`; без неё сервер висит
в `starting`, workflow засчитывает это как успех с предупреждением.

## Что важно помнить

- **Данные.** Рабочая база `data/radar.sqlite` лежит в томе сервера и переживает перезапуски.
  При переустановке сервера (**Reinstall**) том очищается: сохраните файл заранее.
- **Остановка.** Бот завершает текущий обход и отправку до 30 секунд. Если панель убивает процесс
  жёстче, увеличьте таймаут остановки в настройках яйца.
- **Автозапуск.** Включите перезапуск при падении в настройках сервера, чтобы бот поднимался сам.
- **Обновление кода** при настроенном автодеплое (раздел 6) происходит само. Вручную:

  ```bash
  git pull
  pip install --user -r requirements.txt
  ```

  затем **Restart**.
- **Логи.** Всё пишется в консоль панели. Уровень подробности меняется переменной `LOG_LEVEL=DEBUG`
  в `.env`.
