## Как отбирались учреждения

В исходном XML 307015 записей `license`. Географический отбор проверял Чувашскую Республику по адресу и данным организации. Для основного отбора использованы статус лицензии «Действует», действующее приложение `Valid` и программы «Основное общее образование» и/или «Среднее общее образование».

Получены 369 уникальных держателей лицензий: 362 школьные организации и 7 иных организаций. Школьное отделение Чебоксарского училища олимпийского резерва включено по дополнительному официальному подтверждению 8–9 классов. Остальные 6 организаций СПО/ВО с общими программами оставлены для отдельной проверки: запись программы в лицензии не доказывает наличие самостоятельной школы для обычного профориентационного выезда. Среди них встречаются учебно-консультационные пункты, связанные с учреждениями исполнения наказаний.

Включены основные и средние школы, гимназии, лицеи, кадетские организации, школы-интернаты и школы для обучающихся с ОВЗ при наличии соответствующей программы. Детсады, учреждения только начального образования, дополнительное образование и обычные колледжи без подтверждения школьного подразделения не добавлены в основной школьный список.

Поля `basic_general` и `secondary_general` означают наличие уровня в лицензии, а не фактический набор 9/11 класса в текущем году. Маршрут ОГЭ/ГВЭ/ЕГЭ для каждой организации отдельно не установлен (`exam_route=not_verified`). Для дополнительных корпусов уровни оставлены NULL: наличие лицензии у головной школы не доказывает распределение классов по каждому зданию. Наблюдавшиеся классы и даты таких сведений указаны в доказательствах.

Адреса сохранены вместе с источниками; юридический адрес отделён от адреса площадки. `area_source` сохраняет район/округ из исходных сведений и не является справочником актуального муниципального устройства. Одноимённые населённые пункты разделяются по типу и району. Для двух деревень Сятракасы в Чебоксарском районе сохранены уточнения прежних сельских поселений из адреса. В текстовом списке город объединяется в одну группу даже при разном написании района в источнике.

## Как трактовать ссылки ВК

- `official_source_link`: школьный сайт, официальный виджет, раздел социальных сетей или официальный образовательный справочник прямо связывает учреждение с группой.
- `candidate`: вероятная группа найдена в поиске, VK Video, справочнике либо в школьной новости без однозначного подтверждения принадлежности. Она отключена в подборке для бота.
- `not_found`: адрес не установлен в выполненном поиске. Это не означает отсутствия группы.

**Официальность и активность — разные проверки.** Наличие ссылки на школьном сайте не подтверждает свежие публикации. Даты последних постов здесь не установлены. Многие страницы edu21.cap.ru возвращали ошибки доступа; часть сведений доступна только в поисковом индексе. ВК также не удалось проверить на полноту ленты. Даты школьных новостей не подставлялись вместо дат постов ВК.

В Excel основной столбец ВК содержит подтверждённые адреса, если они есть; иначе найденных кандидатов. Все кандидаты также вынесены в отдельный столбец. Индивидуальный статус каждой связи находится в JSON и в `unit_communities`. Лист «ВК» показывает сводный статус сообщества по связанным учреждениям. У одного учреждения может быть несколько адресов. Старый числовой URL и новый короткий адрес могут оказаться одним сообществом: такое тождество без проверки не предполагается.

## Подключение к будущему боту

Сущности: `organizations` → `units` → `unit_communities` → `communities`. ИНН идентифицирует юридическое лицо, `unit_id` — конкретную запись школы или корпуса. `parent_unit_id` связывает дополнительную площадку с основной.

Представление `v_monitor_targets` содержит только связи с подтверждённым официальным источником и включает общее сообщество школы и её корпусов один раз. `monitor_enabled=1` означает включение в эту подборку; сам процесс опроса не запущен. Отсутствие подтверждённой текущей активности не исключает группу из первого проверочного опроса.

`group_id` — положительный числовой идентификатор группы, `vk_owner_id` — его отрицательное значение. У коротких адресов идентификатор часто неизвестен: сначала надо разрешить адрес через доступный официальный интерфейс ВК и объединить дубли по числовому ID. Не следует подставлять в `owner_id` выдуманные значения. `community_key` до такой проверки может иметь вид `vk:slug:имя`.

`monitor_checks`, `posts` и `achievement_candidates` созданы пустыми. Пост уникален по `(owner_id, post_id)`. База не содержит профилей учеников, личных страниц или придуманных достижений. Для будущего поздравления сохраняйте ссылку на публичный пост учреждения и результат редакторской проверки.

Пример чтения без дополнительных Python-библиотек:

```python
import sqlite3

db = sqlite3.connect("schools_chuvashia.sqlite")
db.row_factory = sqlite3.Row
for row in db.execute("SELECT * FROM v_monitor_targets ORDER BY canonical_url"):
    print(dict(row))
```

## Сверка комплекта 13.09.2026

Во всех основных форматах сверены 372 школьные записи по `unit_id`: ссылка ВК заполнена у 370, у двух адрес группы не установлен. Из этих 370 записей 62 имеют подтверждение официальным источником, 308 содержат только кандидатов. В таблице сообществ 365 различных нормализованных адресов, включая альтернативные группы. Это не число школ: некоторые корпуса используют общую группу.

Исправлены 53 устаревших примечания о ненайденной ссылке в JSON, SQLite, CSV и Excel. Статусы подтверждения и сами адреса сохранены. Исходные материалы в `evidence/` отражают этапы поиска и могут содержать старые результаты. Файлы `new_vk_found.csv` и `still_missing_vk.csv` относятся к добору 13.09.2026.

В `queries.sql` добавлены запросы для проверки общего числа записей с ВК и для получения всех найденных связей, включая кандидатов. `v_monitor_targets` по-прежнему содержит 59 сообществ с подтверждёнными связями. У 98 записей сообществ числовой ID ещё не установлен; перед опросом нужно разрешить короткий адрес и проверить дубли.

Проверки базы включают обе команды: `PRAGMA integrity_check` и `PRAGMA foreign_key_check`. Первая не проверяет внешние ключи, поэтому они проверены отдельно по [документации SQLite](https://www.sqlite.org/pragma.html#pragma_integrity_check). Результаты сверки данных сохранены в `validation_report.json`. SHA-256 каждого файла указан в `manifest.json`; сам manifest в свой перечень не включён.
