# Уведомления по территориям Чувашии

Версия данных: 13.09.2026. Здесь описана подготовленная структура SQLite для будущего бота. Процесс мониторинга, бот и отправка уведомлений не запускались. Таблицы профилей и настроек в поставляемой базе пусты.

## Территории и идентификаторы

Справочник содержит **23 муниципальных образования: 21 муниципальный округ и 2 городских округа — Чебоксары и Новочебоксарск**. Состав сверён с [официальным перечнем Чувашстата](https://21.rosstat.gov.ru/list_of_municipalities).

`municipalities` содержит поля `municipality_id`, `name`, `municipality_type`, `source_id`, `checked_at`. Поле `units.municipality_id` связывает школу или отдельную площадку со справочником. Названия и идентификаторы также присутствуют в основных экспортах JSON, CSV и Excel. Файл `municipalities.csv` позволяет загрузить список территорий отдельно.

`municipality_id` — **внутренний стабильный идентификатор этого реестра, не код ОКТМО**. Кнопки бота сохраняют именно ID из справочника. Название служит подписью кнопки; строковый поиск по `area_source` для фильтрации не нужен. `area_source` сохраняет исходную формулировку адреса и может содержать старое название района.

Город Алатырь относится к Алатырскому муниципальному округу, Канаш — к Канашскому, Шумерля — к Шумерлинскому. Чебоксарский муниципальный округ и городской округ город Чебоксары — отдельные значения. Внутригородские районы Чебоксар не образуют дополнительные территории этого справочника. Сосновка, Новые Лапсары, Северный и Чандрово в составе городского округа Чебоксары не относятся к Чебоксарскому муниципальному округу; одноимённые населённые пункты в других местах различаются по полному адресу.

## Профиль и индивидуальные настройки

Профиль — получатель или отдельная конфигурация уведомлений. Для Telegram можно принять формат `telegram:chat:<chat_id>`, где `<chat_id>` — заменяемый шаблон, а не настоящий идентификатор чата. Доступ к изменению профиля проверяет приложение.

- `notification_profiles(profile_id, default_enabled)` хранит общий режим профиля.
- `notification_region_settings(profile_id, municipality_id, enabled, updated_at)` хранит только индивидуальные исключения и время изменения.
- Если исключения для территории нет, применяется `default_enabled` профиля.
- Значения `enabled` и `default_enabled`: `1` — включено, `0` — выключено.

Новый профиль создаётся с `default_enabled=1`: все 23 территории включены. Повторное создание профиля не должно затирать выбор пользователя. Команда «Всё выключить» ставит общий режим `0` и удаляет исключения; «Всё включить» ставит `1` и также удаляет исключения.

Представление `v_notification_regions` возвращает эффективные настройки территорий для существующих профилей. Представление `v_notification_targets` возвращает доступные для профиля сообщества с учётом территорий и прежних ограничений подключения.

## SQL для бота

На каждом подключении к SQLite включайте внешние ключи:

```sql
PRAGMA foreign_keys = ON;
```

Именованные параметры `:profile_id`, `:municipality_id`, `:enabled` передаются через механизм параметров драйвера SQLite. Не подставляйте значения конкатенацией строк. В Python `sqlite3` их можно передать словарём, например `{"profile_id": "telegram:chat:<chat_id>"}` после замены шаблона реальным ID в приложении.

Создать профиль, сохранив настройки уже существующего:

```sql
INSERT INTO notification_profiles (profile_id, default_enabled)
VALUES (:profile_id, 1)
ON CONFLICT (profile_id) DO NOTHING;
```

Включить или выключить одну территорию:

```sql
INSERT INTO notification_region_settings
    (profile_id, municipality_id, enabled, updated_at)
VALUES (:profile_id, :municipality_id, :enabled, CURRENT_TIMESTAMP)
ON CONFLICT (profile_id, municipality_id)
DO UPDATE SET enabled = excluded.enabled,
              updated_at = excluded.updated_at;
```

Вернуть территорию к общему режиму профиля:

```sql
DELETE FROM notification_region_settings
WHERE profile_id = :profile_id
  AND municipality_id = :municipality_id;
```

Выключить всё, включая ранее включённые исключения:

```sql
BEGIN;
UPDATE notification_profiles
SET default_enabled = 0
WHERE profile_id = :profile_id;
DELETE FROM notification_region_settings
WHERE profile_id = :profile_id;
COMMIT;
```

Включить всё, включая ранее выключенные исключения:

```sql
BEGIN;
UPDATE notification_profiles
SET default_enabled = 1
WHERE profile_id = :profile_id;
DELETE FROM notification_region_settings
WHERE profile_id = :profile_id;
COMMIT;
```

Многооператорные примеры выполняйте отдельными параметризованными вызовами внутри одной транзакции драйвера. В Python `sqlite3.executescript()` не принимает словарь параметров и не подходит для непосредственного исполнения этих шаблонов.

Получить список территорий с эффективным состоянием переключателей:

```sql
SELECT *
FROM v_notification_regions
WHERE profile_id = :profile_id
ORDER BY municipality_id;
```

Получить цели опроса для профиля:

```sql
SELECT *
FROM v_notification_targets
WHERE profile_id = :profile_id
ORDER BY canonical_url;
```

Если профиль не создан, эти представления не возвращают для него строк. Не интерпретируйте это как просьбу пользователя включить все уведомления: сначала явно создайте профиль при его регистрации.

## Пример подключения из Python

Запускайте код из папки распакованного комплекта. Профиль создаётся один раз при регистрации получателя; далее бот использует тот же `profile_id` для его переключателей.

```python
from notification_filters import (
    connect_database, create_profile, list_regions, list_targets,
    set_region_enabled, set_all_enabled,
)

db = connect_database("schools_chuvashia.sqlite")
profile_id = "chat:12345"  # пример; подставьте ID получателя
try:
    create_profile(db, profile_id)  # только при первой регистрации
    set_region_enabled(db, profile_id, "ru21-city-cheboksary", False)
    regions = list_regions(db, profile_id)  # состояния для кнопок
    targets = list_targets(db, profile_id)  # группы включённых территорий

    # Примеры обработчиков кнопок «Выключить всё» / «Включить всё»:
    set_all_enabled(db, profile_id, False)
    set_all_enabled(db, profile_id, True)
finally:
    db.close()
```

`set_region_enabled(..., True)` включает выбранную территорию. Повторный вызов `create_profile()` для существующего профиля вызывает `ValueError`. Изменения вне внешней транзакции сохраняются сразу; внутри неё окончательный `commit` или `rollback` выполняет вызывающий код. Этот модуль готовит настройки и выборку групп; обработчики кнопок, чтение постов и отправку уведомлений нужно подключить в самом боте.

## Какие группы подключаются

Наличие ссылки ВК и включение территории — разные условия. Из 372 школьных записей у 370 есть ссылка: 62 записи имеют подтверждение официальным источником, у 308 есть только кандидаты. После объединения общих групп прежняя подборка `v_monitor_targets` содержит **59 сообществ**. Именно эта проверенная подборка служит основой территориального отбора.

Включение территории **не подключает автоматически непроверенные связи**. Отбор требует одновременно `scope='school'`, `monitor_enabled=1`, `official_status='official_source_link'` и включённую территорию профиля. Даже ошибочный признак `monitor_enabled=1` у кандидата не добавит его в `v_notification_targets`. Статусы `candidate` и признаки допуска к мониторингу сохраняются. Текущая активность сообществ не подтверждена; включение в выборку ещё не означает, что там есть свежие посты.

Когда одно сообщество связано с несколькими школами или площадками в разных территориях, достаточно одной включённой территории с допустимой связью, чтобы сообщество осталось целью профиля. В представлении цель представлена один раз для этого профиля. Поля `unit_ids`, `school_names`, `municipality_ids`, `municipality_names` перечисляют только включённые связи, участвующие в отборе; `unit_ids` и `school_names` разделены точкой с запятой, а `municipality_ids` и `municipality_names` — запятой. Отключение одной территории не должно прекращать опрос общей группы для других включённых территорий.

Для нескольких профилей опрашивайте одно сообщество один раз, затем распределяйте результаты по профилям. Опрос, хранение найденных постов и отправка сообщений — отдельные этапы.

## Фильтрация конкретного поста и повторные уведомления

Фильтр целей решает, какие сообщества можно читать. Он не определяет автоматически, какой школе посвящён конкретный пост общей группы. Если группа пишет об учреждениях разных территорий, точная фильтрация уведомлений требует сопоставить пост с `unit_id`, затем проверить территорию этой площадки для получателя. До такого сопоставления отключение территории не гарантирует исключение всех упоминаний её школ из общей группы.

При первом запуске установите точку отсчёта ленты. Не рассылайте весь найденный архив как новые достижения. При перезапуске сохраняйте настройки профилей и продолжайте обработку с сохранённой позиции; не создавайте заново подписки и не отправляйте прежние уведомления повторно. Включение ранее отключённой территории само по себе не означает заказ исторической рассылки. Отдельную выдачу архивных достижений следует оформлять отдельным действием пользователя.

В исходной схеме пост уникален по `(owner_id, post_id)`. Для реальной рассылки боту дополнительно потребуется учёт доставки по получателю и посту, а также сохранение курсора обработки. Эти процессы не запускаются SQL-примерами выше.

## Файлы реализации

- `schools_chuvashia.sqlite` — данные, справочник, таблицы настроек и представления.
- `schema.sql` — актуальная структура; `queries.sql` — примеры запросов.
- `municipalities.csv` — 23 территории и их ID.
- `notification_filters.py` — вспомогательные операции с настройками; фактические функции и параметры описаны в самом файле.
- `tests/test_notification_filters.py` — проверки изоляции профилей, переключателей, общих групп и исключения кандидатов.

Запуск проверок из корня распакованного комплекта:

```bash
python -m unittest discover -s tests -v
```
